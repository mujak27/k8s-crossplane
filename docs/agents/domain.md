# Domain docs

Use a single-context layout:
- GLOSSARY.md at the repository root.
- Architecture decisions under docs/adr/.

If GLOSSARY-MAP.md exists, follow its context-specific pointers instead.

Before exploration, read the glossary and relevant ADRs when present.
Proceed silently when absent; create them lazily as terms or decisions
are resolved.

Use glossary terminology in plans, tickets, and tests.
Surface conflicts with existing ADRs before proposing changes.
